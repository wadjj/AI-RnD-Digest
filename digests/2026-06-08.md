### Simon Willison's Weblog

**datasette-agent-edit 0.1a0**

Simon Willison 发布了 `datasette-agent-edit` 的 alpha 版本，这是给 Datasette Agent 准备的基础编辑插件。它复用了 Claude text editor tool 的思路，把 `view`、`str_replace`、`insert` 三类文本编辑能力抽出来，方便后续在 Markdown 协作编辑、SQL 更新、SVG 修改等场景里复用。重点不是又做了一个编辑器，而是把 agent 修改文本时最容易出错的“定位、替换、插入”动作标准化。

https://simonwillison.net/2026/Jun/7/datasette-agent-edit/#atom-everything

**micropython-wasm 0.1a2**

Simon 给 `micropython-wasm` 增加了 CLI，方便用户不用先写 Python 代码就能直接试运行 MicroPython WASM sandbox。这是他更大一套 Datasette Agent sandbox 工作的一部分：让任意代码执行变得更容易测试，也让“Try it yourself”这样的文档段落更容易落地。

https://simonwillison.net/2026/Jun/6/micropython-wasm/#atom-everything

**Running Python code in a sandbox with MicroPython and WASM**

这篇是 Simon 对 Python sandbox 的长文复盘。他想解决的问题是：Datasette、LLM、sqlite-utils 这类插件系统很强，但 Python 插件天然拥有过高权限，坏插件或恶意插件可能读文件、访问网络或破坏宿主应用。Simon 的方向是把 MicroPython 编译到 WebAssembly，再用 `wasmtime` 在 Python 应用里执行，从而获得内存限制、CPU fuel、文件和网络访问控制，以及可选择暴露 host functions 的能力。

最有价值的细节是 persistent interpreter state：普通 WASM 执行一次就退出，但 Datasette Agent 需要变量和函数能跨调用保留。他最后用线程、请求队列和 host function 做了一个 session 模式，让 WASM 内部的 MicroPython 等待下一段代码并返回结果。这个实现仍是 alpha，但它给“agent 需要运行代码，又不能把整台机器交给它”这个问题提供了一个很实用的方向。

https://simonwillison.net/2026/Jun/6/micropython-in-a-sandbox/#atom-everything
